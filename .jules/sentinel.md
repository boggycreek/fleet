## 2026-11-06 - CLI Flag Injection and Malformed Input in IDE Extension Wrappers
**Vulnerability:** Input prompts (`showInputBox`) and unvalidated command arguments in IDE plugins passing user strings directly into CLI argv vectors (`execFileAsync(cliPath, ['agent', 'start', agentName])`) or external URIs (`vscode://...`) allow CLI flag injection (e.g. entering `--all` to inadvertently affect all containers) and malformed URI schemes.
**Learning:** Even when avoiding shell interpolation by using `execFile`, CLI utilities interpret leading hyphens (e.g. `-f`, `--all`) as command flags rather than positional arguments unless strict input validation or `--` argument termination is enforced.
**Prevention:** Strictly validate user-supplied identifiers against the canonical backend format regex (`^[a-z0-9][a-z0-9_-]{1,63}$`) in frontend prompts and command dispatch handlers before passing them to CLI processes or URI parsers.

## 2026-11-06 - Diagnostic Tool Credential Leakage & Unbounded Input Vectors
**Vulnerability:** In diagnostic and environment inspection tools (`agent-doctor-mcp`), custom endpoint URLs containing embedded credentials (`http://user:pass@host`) were reflected into structured tool output without redacting basic auth userinfo. Additionally, environment variable inspection used an incomplete substring blacklist (`PASSWORD`) that missed common secret keys like `*_PASS`, `*_PASSPHRASE`, `*_CERT`, `*_COOKIE`, and `*_SESSION`, while endpoint lists and execution timeouts lacked bounds (permitting DoS via unbounded connections or timeouts).
**Learning:** Diagnostic reflection tools often serialize input arguments directly back into diagnostic output summaries. Without explicit URL credential masking (`url.URL.Redacted()`) and input bounds, diagnostic tools become vectors for both credential leakage and DoS.
**Prevention:** Always mask URL userinfo credentials in diagnostic output via standard library helpers (`u.Redacted()`), enforce strict bounds on input collection lengths and timeouts, and ensure secret key blacklists include short root tokens (`PASS`, `CERT`, `COOKIE`, `SESSION`).
